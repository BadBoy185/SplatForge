# M11 Gaussian training

M11a supplies the [evidence ledger](M11_EVIDENCE.md), explicit candidate recipes and
bounded sequential comparison. M11b supplies validated external LichtFeld handoff and
the SplatForge-owned managed gsplat worker. Verification and empirical results are
recorded below. There are no adopted universal quality presets. M7c production VPR
and representative M8 mapper recommendation remain separate pending work. M12 is not
started.

## Boundary and immutable inputs

```text
PreparedDatasetComponent v1
  -> TrainingPlan + frozen TrainingSettings v1 + exact runtime identity
  -> external python -I SplatForge gsplat worker
  -> immutable backend checkpoint(s)
  -> independently validated GaussianScene v1
PreparedDatasetSet v1 -> separate component jobs -> GaussianSceneSet v1 receipt
```

CLI delegates to TrainingService; the injected TrainingBackend owns external execution.
Core and the application host import no Torch, gsplat or CUDA extension. The optional
worker package is shipped with SplatForge but runs under an explicitly configured
separate Python environment. It registers only SplatForge package paths, without
adding the application's dependency directory to the worker's dependency search path.
Python isolated mode ignores ambient PYTHONPATH and user site-packages.

M10 is unchanged. Each job consumes exactly one published conventional component,
with `images/`, `sparse/0/{cameras,images,points3D}.bin` and `dataset.json`. DatasetSet
members never enter one trainer invocation and scenes are never merged. Readers
recheck published lineage, images and sparse content. Training changes cannot execute
or invalidate M7/M8/M9/M10. Source originals are not training inputs.

Initialization uses sparse XYZ and RGB, canonically ordered by numerical point/color
content rather than native point IDs. At least four seeds are required for the
nearest-neighbor initialization. World normalization and pose optimization are false.
Camera extent scales position learning rates and densification thresholds; it does
not transform coordinates. Public means remain in the M10 world coordinate system,
with the same camera convention and `unknown_arbitrary` scale, never meters.

## Strategies and resolved settings

One backend implements two explicit stable methods: `gsplat.default` and `gsplat.mcmc`.
The historical `training.gsplat` catalog entry is not an executable alias. Saved old
project intent, including the prototype `balanced` label and `training.none`, is not
silently migrated or used as hidden numerical settings.

| Setting | Reference candidate |
| --- | --- |
| Initialization / pose optimization / normalization | SFM / false / false |
| Full reference target | 30,000 completed steps |
| SH degree / degree interval | 3 / 1,000 steps |
| L1 / Gaussian-window SSIM loss | 0.8 / 0.2 |
| Seed | 42 |
| Data factor | 1 unless explicitly resolved otherwise |
| Evaluation | none; all views train by default |
| Checkpoint / evaluation cadence | 7,000 / 7,000 steps |
| Antialiasing | false |
| Default grow_grad2d | 0.0002 |
| AbsGrad candidate grow_grad2d | explicitly 0.0008 |
| MCMC cap_max | explicitly 1,000,000 |
| MCMC noise_lr / opacity_reg / scale_reg | 500,000 / 0.01 / 0.01 |
| Default refinement start / stop / interval / reset | 500 / 15,000 / 100 / 3,000 |
| MCMC refinement start / stop / interval | 500 / 25,000 / 100 |

All learning rates, clipping planes, opacity initialization and strategy settings are
typed fields saved in each run. They follow the verified upstream reference direction;
the worker is not a promise of bitwise equivalence to an upstream example. It owns its
bounded image loader and differentiable valid Gaussian-window SSIM implementation.
AbsGrad must be enabled in both rasterization and DefaultStrategy. Enabling its typed
flag does not secretly change the recorded threshold. Antialiasing has a positive
kernel/backward/optimizer probe. Combined AbsGrad+AA and MCMC+AA are refused until
that exact combination has positive capability evidence; no option is silently disabled.

`data_factor` uses explicit integer output dimensions and matching per-axis intrinsic
scaling. BOX resizing happens in a bounded 512 MiB CPU image cache, without writing
resized images into M10. Device image tensors are loaded one training observation at
a time. No random initialization, pose/appearance optimization, sparse/visible Adam,
PPISP, bilateral grid, compression, multi-GPU, 2DGS or 3DGUT route is enabled.

## Exact optional runtime

The validated release family is gsplat **1.5.3**, official tag commit
`937e29912570c372bed6747a5c9bf85fed877bae`, under Apache-2.0. A runtime cannot identify
itself as `latest` or a branch name. Worker and backend identities include source
hashes, exact package versions, installed numerical Python/native code bytes (including
Windows wheel sibling DLL directories such as numpy.libs/scipy.libs),
stable wheel/commit identity where available, Python executable/base/DLL identity,
Torch CUDA build, actual `cudaRuntimeGetVersion`, NVIDIA driver, GPU ordinal/UUID/name,
compute capability and total device bytes. Local installation locators are excluded
from numerical identity. Seeded GPU execution is **not bitwise determinism evidence**.

The owned capability worker imports Torch, executes a CUDA tensor operation, imports
gsplat, rasterizes, backpropagates and performs optimizer/strategy steps for Default,
AbsGrad, antialiasing and MCMC (including relocation/noise); real transport tests also
exercise Gaussian growth. Generic NVIDIA detection
and installed package versions cannot mark this runtime runnable. Doctor reports the
implemented methods as unprobed and points to the dedicated capability command.
Every numerical segment reprobes the frozen runtime; mismatch refuses resume/execution.

The product never installs or upgrades packages. Runtime JSON is a local locator:

```json
{
  "python": "C:\\TrainerRuntime\\Scripts\\python.exe",
  "environment": {}
}
```

An explicitly configured child toolchain environment may contain PATH/INCLUDE/LIB,
CUDA_HOME/CUDA_PATH, TORCH_EXTENSIONS_DIR, TORCH_CUDA_ARCH_LIST and bounded existing
MSVC build variables. It never changes global PATH. Provisioning is a separate manual
development action. For the local validation, an ignored `sample_data/m11-runtime`
venv used Python 3.12.10, Torch 2.7.1+cu128 and CUDA toolkit 12.8 with existing MSVC.
The PyPI pure wheel's Windows JIT route failed on `-Wno-attributes`; the **unchanged
release sdist** successfully built a native Windows wheel instead. Its SHA-256 is
`f2f89630cd488c6cbd5681ff4e470d8c9d808a5b51ff510363cae33ea9b4d680`.
All 24 installed gsplat Python files match the exact upstream tag bytes. No upstream
commit fallback, Graphdeco dependency or global Python installation was needed.

## Commands and external handoff

Commands return structured JSON; lifecycle commands are the existing generic ones.

```powershell
splatforge training handoff "C:\Scenes\Example" --dataset-run <m10-run>
splatforge training capability "C:\TrainerRuntime\runtime.json"
splatforge training plan "C:\Scenes\Example" --dataset-run <m10-run> --runtime runtime.json --strategy default
splatforge training run "C:\Scenes\Example" --dataset-run <m10-run> --runtime runtime.json --settings training.json
splatforge training show "C:\Scenes\Example" <scene-or-checkpoint-run>
splatforge training compare "C:\Scenes\Example" --dataset-run <m10-run> --runtime runtime.json --settings benchmark.json
splatforge run active "C:\Scenes\Example" --json
splatforge run progress "C:\Scenes\Example" <active-segment-run> --json
splatforge run cancel "C:\Scenes\Example" <active-segment-run>
splatforge run recover "C:\Scenes\Example" <interrupted-segment-run>
```

`--strategy default|mcmc` and typed `--settings` must agree. Optional `--limits` is typed
TrainingLimits JSON. Plans report component membership, image counts/resolutions,
sparse seeds, unknown scale, full resolved settings, cadences, capability/GPU/VRAM,
cache status and explicitly **unknown** resource class/peak VRAM estimate. Device
capacity is not a fabricated peak-allocation prediction.

Handoff independently validates the existing M10 directory and reports its exact path,
layout, image/camera/point counts, digest and scale. No data copy is needed. Open that
directory manually as a COLMAP dataset in LichtFeld; choose a separate external output
directory and retain M10 as read-only input. Optional native binary detection records
file identity, without executing GUI, version command or an unverified CLI. Absence of
LichtFeld is not a managed-training failure. A manual open is separate evidence.

LichtFeld is external GPLv3-or-later (with its upstream NVIDIA-library exception).
Dataset/PLY interoperability is the boundary; no GPL implementation is linked/copied.
The original Graphdeco implementation remains research/reference-only because its
license restricts commercial use. See the pinned [license/research ledger](M11_EVIDENCE.md).

## Checkpoints, resume and numerical identity

Checkpoint cadence divides a component into independent persisted training segments.
Each segment owns a disposable process, attempt and workspace. An evaluation boundary
may also close a checkpoint segment. Completed checkpoints survive cancellation of a
later segment or final export. There is no actively written checkpoint adoption.

```powershell
# Same immutable max_steps/schedule; stop is an execution boundary, not a quality preset.
splatforge training run "C:\Scenes\Example" --dataset-run <m10-run> --runtime runtime.json --settings training.json --stop-after-step 50
splatforge training run "C:\Scenes\Example" --dataset-run <m10-run> --runtime runtime.json --settings training.json --resume-run <checkpoint-run>
```

Native state includes parameters, optimizer moments, scheduler, strategy state, Python,
NumPy, Torch CPU and selected-device CUDA RNG state. Resume records
`resumed_from_checkpoint` and starts at that completed step. Dataset semantic identity,
strategy, **all frozen numerical settings including max_steps**, worker/runtime identity
and checkpoint schema must match. Changing only a terminal training target is not
supported; plan a new run. `--stop-after-step` leaves the original horizon unchanged.

Training recipes include the exact component semantic digest, method, resolved numerical
settings, split, seed, data factor, target steps and exact backend identity. They exclude
artifact/run UUID, path, workspace, time, log text, progress, ETA and refusal-only resource
budgets. Checkpoint recipe additionally binds completed step and compatibility identity.
Native file hashes protect opaque state; they are not a public scene representation.
Scene recipe is the training recipe; scene semantics hash actual canonical Gaussian
numbers, convention and scale. Same numerical M10 content under a fresh artifact UUID
can reuse a valid scene while the new run retains current input provenance.

## Artifacts and independent validation

```text
artifacts/training_checkpoint/<id>/
  checkpoint/state.pt
  checkpoint.json
  worker_result.json  worker_receipt.json  worker_events.jsonl  manifest.json
artifacts/gaussian_scene/<id>/
  scene.ply  scene.json
  worker_result.json  worker_receipt.json  worker_events.jsonl  manifest.json
artifacts/gaussian_scene_set/<id>/
  scene_set.json  manifest.json
```

Checkpoint/scene JSON records derived recipe, numerical/backend identity, compatibility
where applicable, resolved settings, native/PLY hash and size, step/count, metrics,
runtime, allocated CUDA peak and checkpoint lineage. Final scenes additionally record
method, SH degree, M10 convention/scale and actual numerical content digest. SceneSet
is only a canonical component-identity-ordered reference receipt, with no merged payload.

The independent reader opens the final PLY on disk after worker teardown. The frozen
portable layout is binary little-endian float32: XYZ, zero normals, f_dc_0..2,
3*((SH+1)^2-1) f_rest coefficients in channel-major order, opacity logits, three log
scales, and normalized wxyz rotation quaternions. Header/line bounds, exact size/count,
finite values, nondegenerate unit quaternions, float32 scale range and exact SH/property
dimensions are mandatory. Row SHA-256 values are sorted through bounded disk-backed
SQLite, preserving duplicates and ignoring row order; negative zero is canonicalized.
Raw PLY hash separately protects the exact transport bytes.

Publication, recovery and cache validate result-manifest hash, strict complete worker
events, settings/recipe/lineage, metadata and actual checkpoint/PLY files. Missing,
partial, corrupt or exit-zero-without-scene output cannot publish. Same-volume immutable
publication and writer/cancellation serialization use the existing repository; no
project/state version migration or second state system is added. Generic cleanup does
not evict training checkpoints or public scenes.

## Protocol, progress, resources and metrics

Worker protocol v1 uses bounded JSONL in an attempt-owned event file; stdout must be
empty, and native/human diagnostics go to bounded stderr. Events have strict sequence,
UTC timestamp, completed step/recipe target, and available count/loss/allocated bytes:
worker.started, dataset.loaded, training.started, training.progress, checkpoint.saved,
evaluation.completed, scene.exported, worker.completed or worker.failed. Malformed JSON,
duplicates, reordering, unexpected events, incomplete output and excessive streams fail
closed. tqdm text is never canonical progress.

M6.5 `training.steps_v1` reports cumulative steps within each checkpoint segment's
explicit terminal target, with the immutable recipe's max_steps also recorded as a
diagnostic. Resume starts at the checkpoint step. Hybrid ETA subtracts initial completed
work from live throughput and successful history samples. Signatures distinguish exact
backend/GPU, strategy, settings/data factor, image-count and resolution buckets. Export
has no new training work. Cache hits, failed and cancelled attempts do not teach timing
history or invent successful completion. Generic `run active` identifies the current
segment's cancellation handle; a finished checkpoint run is not that later handle.

Default per-segment limits: 14,400 seconds, 16 GiB native checkpoint bytes, 8 GiB final
PLY bytes, 8 MiB per captured/event stream and 10 million Gaussians. Checkpoint serialization
is bounded during writes; a partial file never becomes an immutable checkpoint. Torch's
positive OutOfMemoryError has `gpu_oom` classification; no resolution, SH, cap or method
fallback follows it. Cancellation waits for the owned Windows process tree and handle
release; unconfirmed teardown quarantines the attempt and blocks retry/publication.

Metrics separate training loss from held-out evaluation. PSNR and valid-window SSIM are
macro averages across explicitly withheld views, with per-source-group aggregates and
evaluation step/count. LPIPS is unavailable in this v1 worker: no local model/weights
were provisioned and no LPIPS execution route is implemented. Adding it requires an
explicit model/weight identity; there is no model download. Duration is accumulated active training-loop time, distinct
from orchestration/probe/loading wall time. CUDA peak is `max_memory_allocated`, never
total application VRAM or reserved bytes; it is sampled at the training-loop boundary
and accumulated across segments. Total device capacity is recorded separately.

The ordinary product route withholds no views. Benchmark settings require explicit,
deterministic membership; the hash-based baseline helper warns about spatial/source
balance. Comparison requires the same dataset, data factor, steps, SH degree, seed,
split and other common numerical settings. Default, explicit AbsGrad and capped MCMC
run sequentially; results/failures and all resource/quality dimensions are retained,
without an overall score or automatic winner.
