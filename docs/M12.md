# M12 Windows-first desktop GUI

M12 provides an optional PySide6 **6.12.0 / Qt Widgets** desktop client of the
existing application services. It does not introduce a processing backend, state
schema, numerical preset, daemon, web server or installer. M13 has not started.

## Install and launch

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[dev,gui]"
.\.venv\Scripts\splatforge-gui.exe
# Equivalent development entrypoint:
.\.venv\Scripts\python.exe -m splatforge_gui.app
```

`gui = ["PySide6==6.12.0"]` is optional. Base CLI startup and backend imports do
not import `splatforge_gui` or Qt. GUI tests skip when the extra is absent.
No trainer, model, COLMAP or FFmpeg installation/download occurs from the GUI.

## Architecture and shared projects

```text
Qt Widgets (splatforge_gui/widgets)
  -> ProjectController / Qt models (splatforge_gui)
  -> GuiFacade (splatforge.application.desktop), built by splatforge.bootstrap
  -> existing Project / Media / Views / Pairs / Features / Matching / Mapping /
     Validation / Selection / Dataset / Training / Execution / Cleanup / Doctor services
  -> Core contracts and existing injected adapters / owned process boundaries
```

Core and Application contain no Qt imports. Widgets import no adapters, process
runners, subprocess, Torch, gsplat or native processing bindings. The desktop facade
composes explicit existing use cases; it owns no feature, mapping, cache or training
algorithm. Reconstruction uses normal individual stage runs and publications.

Project creation/open/save uses ProjectService. Source ingest uses MediaService.
CLI and GUI share project intent, inventories, state.sqlite, run snapshots and
immutable manifests. Opening/Refresh rebuilds presentation from those authoritative
records, including projects the GUI has never seen. There are no required GUI fields
in project.json, no migrations and no numerical state in QSettings.

Workflow status represents indexed publication/lifecycle evidence, not file presence.
Evicted outputs need recomputation. A completed historical publication does not assert
that its recipe still matches edited intent: Plan/current application checks determine
consumer compatibility and cache eligibility. No whole-config cache key is added.

## Navigation and settings

Supported historical state v1/v2/v3 projects open without rewriting either store.
Unavailable old progress/failure-category fields stay unavailable. Diagnostics directs
the user to the existing explicit backup/upgrade command before media processing.

Home summarizes sources, published workflow results, latest validation and active work.
Create/Open, recent projects and project-directory drag/drop are available without a
project. Missing recent paths are marked unavailable and removable; never recreated.

Sources uses a stable-UUID QAbstractTableModel. Add Files, nonrecursive Add Folder,
media drag/drop and Balanced/local verification delegate ingest/verification. Folder
enumeration stops above 2000 entries, sorts deterministically and confirms the exact
supported/ignored count. It never traverses subfolders, symlinks or junctions.
Originals remain read-only external references. Source verification distinguishes
recorded full-hash evidence from metadata reuse. Photos have bounded previews;
videos use already materialized selected views rather than UI-thread video decoding.
The paged gallery loads 100 references at a time.

Guided presents mapper, existing M7 stage profiles/pairing, dataset maximum side and
training strategy/steps/data factor/MCMC cap. Advanced exposes exact validated typed
JSON, storage controls and full diagnostics. Important widgets have stable objectNames.
Qt keyboard navigation, labeled controls, text status and scrolling support high DPI.

JSON editors pretty-print actual Pydantic settings, reject malformed JSON/comments,
unknown forbidden fields, invalid bounds/enums and nested strategy errors, and show
field paths. Apply is disabled after every edit until validation succeeds. Training
and dataset editors can restore their actual contract defaults.
Applying exact reconstruction JSON synchronizes the common mapper/profile/pairing
controls. Changing one common choice preserves unrelated exact numerical settings.

Project intent is edited through its preserved settings envelopes. Staging current
reconstruction method settings as intent creates an unsaved draft; Save uses
ProjectService's revision check. Resolved M7 profile settings, rather than a hidden
quality label, are saved. Save/Discard/Cancel protect close/switch. Unknown saved
methods/settings survive opening and do not block unrelated dataset/results work.

Operational candidate-pool/resource options, verification/policy options, explicit
input run references, dataset max_image_size and M11 TrainingSettings are visibly
run-only unless represented in/staged into an existing project intent slot. Historical
prototype max_frames/reject_blur fields remain preserved; they are not claimed as
implemented selection limits or translated into new quality thresholds. Actual run
settings and bounds are inspectable before execution. No Fast/Medium/High/Max whole
pipeline preset or M11 quality recommendation is introduced.

## Execution, progress and recovery

Project actions support Ctrl+N, Ctrl+O, Ctrl+S, F5 and Ctrl+,. Recent projects and
gallery items support Enter activation. Startup shows Home without a project;
the remembered page is restored after opening a project.
Cancellation requested during preflight is forwarded when an owned operation publishes
its active application run handle; no early Cancelled status is inferred.

TaskExecutor uses a fresh auto-deleting QRunnable for each callable and queued
started/result/error/finished signals. Plain typed results and full tracebacks cross
the boundary. A reserved control pool keeps cancellation/progress reads from waiting
behind long processing/probe jobs. Controllers and Qt objects stay in the GUI thread; QImage decode occurs
in workers, and QPixmap conversion stays in the GUI thread. Each operation constructs
a fresh facade and appropriate services in its worker. Stateful adapters are not shared
between unrelated jobs. Project writer locking remains authoritative.

A 750 ms timer polls active M6.5 progress asynchronously. Overlapping polls are skipped;
project generations discard obsolete responses. Determinate steps show actual progress,
phase-only mapping/dataset work remains indeterminate, and ETA is shown only when
provided. Bounded observation diagnostics expose available loss/Gaussians/allocated
CUDA peak and step counts; checkpoint choices come from published indexed artifacts.
Cache hits have no fabricated execution history. Errors are concise, with Copy Details
and expandable tracebacks; local rotating logs retain at most four 1 MiB files.

Cancel writes the existing application cancellation request and remains Cancelling
until backend lifecycle/teardown resolves. Ingest uses the existing cooperative
cancellation bridge. Reconstruction checks cancellation between existing service calls.
Active/unresolved work blocks incompatible mutations. Diagnostics exposes exact run
inspection and normal publication recovery; no attempt directory manipulation occurs.

Orchestration lives in the GUI process. Closing during active work offers only
**Cancel run and close** or **Return**. Closing waits for worker completion and confirmed
lifecycle; unresolved teardown leaves Recovery visible. There is no Continue in
background option and no claim of daemon-based execution/detachment.

Existing cleanup apply and atomic project metadata calls have no mid-call cancellation
contract. Their Cancel control stays disabled; closing offers Return until completion.
The GUI never pretends to interrupt those calls or detach their owning thread.

## Reconstruction, dataset and training

Reconstruct resolves saved known methods and allows explicit Global, Incremental and
Hierarchical choices. Plan positively probes the selected mapper and resolves the
existing M7 profile/explicit route. Run binds that exact resolved M7 route; changed
settings/tool paths require another Plan. There is no mapper/runtime failure fallback.
Advanced uses the existing MapperSettings union, including Global v2 acceleration,
and explicit run-only calibration policy/settings. Existing capability and run checks
refuse unsupported choices; preserve_priors remains the default.
Selected views/pair count/disk/cache information without an aggregate planner remains
explicitly unavailable or known only after its corresponding stage. No estimate is
invented. Sequential and reference Exhaustive are labeled honestly; offline retrieval
can be configured through exact settings with its explicit published retrieval run.
Production multi-video VPR remains pending.

M9 inspection shows the exact report and measurements: registration, components,
source-group coverage, camera issues, reprojection and triangulation availability.
Policy selection can return ambiguous/blocked without publishing. Manual selection
starts empty; Advanced permits multiple separate components. The dialog shows each
component's coverage/status/issues. Multiple choices explicitly mean separate
datasets/scenes and coordinate systems. Applicable FAIL overrides require exact issue
checkboxes, a nonempty reason and explicit confirmation. Warnings require no override.

Dataset takes an explicit published selection run. Plan/Prepare pass typed M10 settings
to the existing service and display its exact image/camera/resource/cache/capability
evidence. The GUI never reopens originals for dataset preparation.

Train uses the managed Default, MCMC and Default + AbsGrad strategies with their real
defaults; **no production quality preset has been adopted**. Capability/Plan/Run use
the existing isolated trainer probe and service. Runtime Python is machine-local;
Advanced can supply an exact scoped TrainingRuntime for this session. Environment
values are not persisted in QSettings. Unsupported strategies are disabled after a
positive probe, without changing the current choice. Exact TrainingSettings exposes
antialiasing/cadence; unsupported combinations are refused by capability checks.
Pose optimization and world normalization are never enabled implicitly.

Resume first calls the application read-only check_resume use case, which reuses M11's
TrainingCheckpoint.require_compatible against exact dataset/settings/runtime identity.
Run repeats that check under the existing writer lease. Changed/stale UI replies cannot
enable Resume. Incompatible checkpoints explain refusal; no zero-step restart is called
resume. Several components remain separate M10/M11 jobs and outputs.

## Results, diagnostics and storage

Results uses Qt models for runs and artifacts, preserving selection by stable UUID.
The bounded index shows the most recent 2000 rows and reports truncation; CLI retains
older history. Runs include stage/status/start/end/duration/cache/failure category and
structured details. Artifacts expose identity, digest, producer, lineage, payload bytes,
pin and storage status. Open Folder/Copy Path use Qt and project-owned inspected paths.

Read-only inspection is an application contract backed by adapter-owned native readers.
It verifies indexed manifest/metadata hashes, then deterministically samples native
centers; this is explicitly not a fresh full numerical integrity validation. Full
consumer/Plan checks remain authoritative. Metadata inventories are compacted before
widget formatting. Sparse/Gaussian centers are capped at 20000 and cameras at 2000.
PLY sampling seeks only selected XYZ records; it never loads a 10M-Gaussian payload.
The lightweight QPainter viewport supports drag/arrow orbit, wheel/plus/minus zoom and
reset/R. Reconstruction preview shows one native component at a time, labeled as such.
**Point-center preview — not final Gaussian rasterization.** No Torch renderer is embedded.

Thumbnail decoding limits encoded bytes/pixels and scaled output. An in-memory LRU
retains at most 128 thumbnails (192-pixel maximum side), with bounded worker queues.
Missing/corrupt previews are isolated from project state and artifacts stay unchanged.

Doctor exposes existing COLMAP/learned/GPU evidence and unknown/unavailable states.
Actual media capability remains unvalidated until ingest/view operations; gsplat's
functional probe is on Train. Configured LichtFeld identity is read without launching
its GUI. Hardware presence alone does not make processing runnable.

Advanced storage delegates cleanup preview/apply and pins. The exact preview lists
artifact IDs, payload paths/bytes and protected IDs. Apply requires confirmation and
the same digest, rechecked by CleanupService under its lease. Pins never override
implicit current/lineage/active protection. There is no generic Clean Everything action.

QSettings stores only geometry, theme (System/Light/Dark), up to 15 recent paths,
last page, Guided/Advanced mode, optional COLMAP/model directory/trainer Python/LichtFeld
paths. It stores no project numerical configuration, checkpoint compatibility or hidden
mapper/trainer values. Removing QSettings does not affect CLI processing.

## Verification and limitations

Tests use deterministic tiny fixtures and fake services, including CLI-to-GUI state,
GUI-to-CLI intent, external active-run discovery, UI responsiveness/timer/cancel,
publication recovery, M9 ambiguity/overrides/separate components, exact dataset request
forwarding, trainer capabilities/resume, bounded inspection, JSON validation, recent
projects, QSettings and import boundaries. GUI tests run offscreen; native Windows smoke
also opens all seven pages at 100% and 150% DPI with spaces/Unicode project paths.
The tested environment is Python 3.12.10, PySide6/Qt 6.12.0 and Windows Server 2022
10.0.20348. Native smoke verifies exposed windows and rendering, not a complete manual
hardware/backend workflow. Final command results are recorded in the task report.

raw-video scrubbing, daemon detachment, installer/updater, cloud/accounts and M13 are
outside M12. No benchmark datasets or quality tuning were run for this milestone.
