# M8b2 Hierarchical, explicit Global acceleration and mapper comparisons

M8a, M8b1 and M8b2 implement the planned classical mapping routes. **M8 technical
implementation is complete. Representative mapper recommendation benchmarking remains
pending.** M7c production VPR benchmarking remains independently pending. [M9](M9.md) now
implements downstream validation/selection; M10 dataset preparation has not started. No default changes,
automatic mapper/BA fallback, quality ranking, custom SfM merge, training or GUI are added.

## Unchanged portable boundary

Every route starts from its declared immutable M7 VerifiedGeometrySet numerical
MappingInput and creates a fresh independent attempt database. Descriptors, raw matches
and undeclared geometry are removed; consumed verified geometry is checked before native
execution. Previously calibrated/mapped databases are never used as another mapper's input.
All routes publish ReconstructionSet v1 and use the existing ReconstructionReader.

Stable membership UUIDs, component and set numerical semantic digests, disjoint public
memberships, explicit unregistered views, native IDs as provenance, camera_from_world,
wxyz, unknown_arbitrary scale and unavailable points/tracks semantics are unchanged.
Equivalent numerical output can have equal set digests across algorithms/devices while
recipes and producer provenance differ. Native point count is a measured count, not quality.

## Hierarchical settings and native execution

`HierarchicalMapperSettings` is frozen, version 1; method ID is
`mapping.colmap_hierarchical`. The installed COLMAP **4.2.1**, commit `bd1fcf6`, help
was inspected. Later releases remain refused until positively validated. Executable SHA-256:
`9418a14c93d4a5eec5eb33ebf48a917403b5faa7ab5d2232f23e50c206d9e427`.

| Typed setting | Default / bounds | Exact native option |
| --- | --- | --- |
| num_threads | 1, 1..64 total | HierarchicalMapper.num_threads |
| num_workers | 1, 1..64, at most total threads | HierarchicalMapper.num_workers |
| image_overlap | 50, 3..10000 | HierarchicalMapper.image_overlap |
| leaf_max_num_images | 500, 3..10000 | HierarchicalMapper.leaf_max_num_images |
| num_image_matches | 20, 1..1000 | HierarchicalMapper.num_image_matches |
| is_hierarchical | true; explicit flat mode allowed | HierarchicalMapper.is_hierarchical |
| branching | exactly 2 | HierarchicalMapper.branching |
| init_num_trials | 10, 1..10000 | HierarchicalMapper.init_num_trials |

`cluster: HierarchicalClusterSettings` reuses the [M8b1 numerical Mapper subset](M8B1.md)
with intentional internal differences: `multiple_models=true`, Ceres/Ceres CPU only,
`extract_colors=false`, no Caspar or Ceres GPU, no sensor-from-rig refinement. Numerical
camera/refinement/initialization/BA/structure-less registration controls retain the M8b1
defaults and bounds. The cluster seed is the explicit default and Mapper random seed.
`cluster.num_threads=-1` and `cluster.init_num_trials=200` are fixed schema constants and
are **not passed**: hierarchy overrides both from its total budget / initialization trials.
There is no independently configured per-worker thread budget. Native code computes
effective workers and divides the total thread budget; SplatForge never multiplies workers
by a full mapper thread setting. Remaining native defaults bind exact executable/DLL bytes.
No arbitrary raw flags are accepted; every required option is checked against actual help.

```text
M7 -> private DB -> overlapping INTERNAL clusters -> Incremental cluster reconstructions
   -> one native Hierarchical merge process -> final native reconstruction manager
   -> validate final disjoint memberships -> ReconstructionSet v1
```

Internal overlapping clusters are **not ReconstructionComponents**. The adapter reads only
the final manager written by hierarchical_mapper, after its native merge process completes.
One final model becomes one component. All disjoint final models are preserved. Zero models,
malformed models or final overlapping hypotheses fail. The overlap error states that native
Hierarchical merging left overlapping reconstruction hypotheses that ReconstructionSet v1
cannot represent. There is no largest/first selection, duplicate-view removal, repeated
model_merger, alignment heuristic or custom reconstruction merge. Native merging gets one
invocation. An attempt-owned empty image directory satisfies native image_path; source media
are not reopened for cosmetic sparse colors.

Doctor separates implementation, command presence, exact supported version, hierarchy and
required Mapper options, executable/runtime identity and real transport integration.
Incremental availability cannot make Hierarchical runnable. Doctor integration evidence is
unknown until an actual integration run supplies separate execution diagnostics.

## Global GPU axes, device identity and refusal

The old **GlobalMapperSettings v1 / mapping.run / MappingRoute** CPU route is unchanged,
including settings serialization, recipe algorithm, backend identity, calibration and cache.
Golden recipe tests were calculated independently with original M8a code at `4ddcfc6`;
a sanitized old-schema snapshot is a regression fixture.

Opt-in `GlobalAcceleratedSettings` version 2 adds a typed `GlobalAccelerationSettings`
object. Its positioning_device and ba_device independently accept `cpu` or a concrete CUDA
ordinal 0..31. This is a distinct `mapping.global_accelerated.run` snapshot discriminator,
not a new mapper: the method remains **mapping.colmap_global**. Existing CPU defaults remain
v1. Explicit v2 CPU/CPU is supported but has its own recipe. The wrapper's inherited v1
CPU fields describe its baseline; acceleration.* controls the actual native GP/BA switches
and device indexes recorded in invocation evidence. No unresolved auto device is
allowed in the frozen route; CLI accepts cpu or gpu:<ordinal>.

| Subsystem | Native controls | Required evidence |
| --- | --- | --- |
| Global Positioning GPU | GlobalMapper.gp_use_gpu / gp_gpu_index | options; concrete runtime device; Ceres CUDA/cuDSS sparse prerequisite; actual GP solver report |
| Global Ceres BA GPU | GlobalMapper.ba_ceres_use_gpu / ba_gpu_index | options; concrete runtime device; Ceres CUDA/cuDSS prerequisite; actual BA solver reports |

NVIDIA inventory, learned inference and Caspar success establish neither subsystem.
GPU planning uses an owned disposable Ceres sparse BA probe with deliberately perturbed
synthetic points, GPU threshold zero and explicit ordinal. It verifies numerical output,
process teardown, exact runtime/executable identity, device consistency and positive Ceres
solver evidence. This probe proves prerequisites, **not real Global integration**. The shared
CUDA identity worker records ordinal, UUID, name, compute capability, driver API and loaded
driver binary SHA-256; pinned bundle runtime bytes include CUDA runtime identity. Device
mask/order environment overrides are refused. The device is rechecked before mapping.
No CUDA state is loaded in the application process. No build/install/download/PATH changes.

Pinned 4.2.1 GP has a 50-image GPU threshold; BA also has a native workload threshold.
Successful tiny CPU execution with GPU flags is insufficient. GP FullReport is observable
at verbosity 2, BA FullReport at verbosity 3; accelerated execution requests level 3.
Bounded native INFO logs must show actual GPU linear algebra and the actual used solver in
complete requested subsystem phases, including subsequent BA refinement. Every emitted
solver report must select GPU, and a positive linear-solver call count must establish
actual numerical work; zero-work convergence alone is insufficient. An earlier GPU
report cannot hide a later CPU solve. Missing,
partial, unknown or incompatible evidence fails/unverifies the requested route rather than
inventing a positive marker. CPU fallback messages, missing CUDA/cuDSS, unavailable device,
GPU initialization failures and native CPU retries are refused even after exit zero.

Doctor exposes separate positioning/ba options, runtime, cuda, cudss and integration facts.
Deep Doctor uses the bounded concrete-device-0 Ceres prerequisite probe. Its successful
prerequisite status does not certify Global integration or select GPU automatically.
Calibration is independent: preserve_priors and explicit view_graph are supported on both
Global CPU and accelerated Global. GPU selection never enables calibration.

Local runtime evidence (2026-10-23): both GP and BA requests are refused because **Ceres was
compiled without CUDA and without cuDSS support**. RTX 5080 / runtime ordinal 0 is observable
with concrete UUID/driver evidence, but no accelerated Global execution is locally validated.
Global CPU remains usable. The three GPU opt-in smoke variants skip with the exact missing
capability; successful mocked GPU contracts do not establish real GPU use.

## Numerical identity, resources, recovery and progress

Recipes bind MappingInput digest, method/settings versions, exact hierarchy/cluster or
acceleration settings, explicit calibration, seeds and numerical executable/runtime/device
identity. They exclude paths, artifact IDs, durations, benchmark/profile labels, refusal
limits, progress, ETA and performance history. Internal cluster order is not public identity.

| Change | Reuse | Recompute |
| --- | --- | --- |
| Global/Incremental/Hierarchical; hierarchy settings/seed | same M7 | M8 |
| GP/BA acceleration axis or concrete GPU/runtime identity | same M7 | M8 |
| Explicit Global calibration | same M7 | M8 |
| Non-binding resource limits; performance history; benchmark order/labels | same M7/M8 numerical cache | no numerical work |
| M9 thresholds | M8 and unchanged M9 measurements | report/selection only |

Hierarchy disk reservation adds overlapping leaf hypothesis / worker concurrency, temporary
models, merge output and validation scratch allowances to the existing private-DB estimate.
This is a conservative estimate, not an exact RAM or peak-disk prediction. Actual workspace,
output/database bytes, file counts and timeout remain enforced refusal bounds; resource
failure never reduces workers or changes settings. Immutable publication, complete native
validation, corruption refusal, orphan recovery and owned Windows tree cancellation use the
existing M8 boundary. Unresolved teardown blocks restart/publication. Resume is stage restart.

`mapping.hierarchical_phases_v1` uses phase mode: preparation, input validation, native
mapping with observed partition/reconstruction/merge headings, and final output validation.
Leaf counts/sizes are diagnostic evidence, never an overall percentage. Complete native INFO
logs are bounded at 32 MiB across at most eight plain files; unsafe/over-budget logs fail.
Global GPU keeps mapping.global_phases_v1. M6.5 whole-job historical ETA partitions signatures
by settings, calibration, runtime and device: Global CPU, GP only, BA only, GP+BA, Incremental
Ceres, Incremental Caspar/device and Hierarchical never share incompatible samples. Failed,
cancelled and cached attempts do not teach history. Performance history never selects methods.

## Sequential mapper comparison and CLI

`MappingComparisonPlan` / `MappingComparisonReport` schema 1 support 1..16 explicitly named
routes from one verification run and exact MappingInput. Normal M8 runs execute sequentially
under existing one-writer/one-active-stage gates. M7 is reused; disposable capability probes
are distinct from recomputing the upstream producer artifacts. Each success references its
normal run/artifact; no reconstructions are copied and no second cache is created.

The report records complete resolved settings/calibration, method/backend/runtime/device,
upstream digest, per-route recipe, hardware profile, succeeded/failed/unavailable/cancelled/
skipped status, API and native process time, estimated workspace, components, registrations,
unregistered views, coverage, native points, semantic digest, cache hit and warnings/failure
category/reason. Missing measurements remain null. Native time sums invoked native stages;
cache hits have no new native duration. Unavailable preflight records available runtime/device
evidence and the refusal reason. Failed runs retain their exact run/recipe where created.
No route substitution occurs. Cancellation stops later routes; unresolved teardown stops work.

JSON output is the small persistent report format; redirect it to an explicit local file.
Canonical reconstructions remain normal immutable M8 artifacts. Report metadata never enters
mapping recipes. There is no quality_score, winner or universal recommendation. A pending
recommendation status records the missing representative benchmarks and M9 quality evidence.
See the [explicit example plan](mapping-comparison.example.json), including Global preserve /
view-graph, GP only, BA only, both GPUs, Incremental Ceres/Caspar and Hierarchical.

```powershell
splatforge mapping run "C:\Scenes\Example" --verification-run <uuid> --method hierarchical --num-threads 4 --num-workers 2
splatforge mapping run "C:\Scenes\Example" --verification-run <uuid> --method global --global-positioning-device gpu:0 --global-ba-device cpu
splatforge mapping compare "C:\Scenes\Example" --verification-run <uuid> --routes docs/mapping-comparison.example.json --json > comparison.json
```

Typed --settings exposes the bounded full subset; it cannot be mixed with individual
numerical flags. --global-positioning-device and --global-ba-device are Global-only;
worker/overlap/leaf CLI flags are Hierarchical-only. Existing commands remain available.

## Real transport fixture and verification

The opt-in Hierarchical fixture uses 12 deterministic perspective views with depth/parallax,
66 real verified pairs, leaf_max_num_images=6, image_overlap=4, total threads=2 and workers=2.
Test-only cluster init_min_tri_angle=8 and fixed known focal/extra parameters avoid unstable
intrinsics in this small fixture. Native evidence shows **two leaves of 10 images**, then
native merging, one final model, **12 registered / 0 unregistered / 1191 points** in the
recorded run. Native duration **0.672 s**, mapping API **16.969 s**. Point counts can vary
slightly with native initialization/order; they are not a deterministic quality assertion.
Reader validation, disjoint public membership, unchanged M7 bytes, repeated cache hit,
overlap-setting recomputation and launched-process cancellation/no publication all pass.
These are transport/contract results only. An earlier fixture with unconstrained intrinsics
left overlapping final hypotheses and was correctly refused, without custom merging.
